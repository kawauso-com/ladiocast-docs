# エラー等の対処

## 設定変更後に起動させることができなくなった場合

Ladiocastを終了して、ユーザ設定を削除してから、立ち上げ直してみて下さい。

LadioCastはApp Sandboxの中で動作するため、設定は、コンテナ`~/Library/Containers/com.kawauso.LadioCast`に保存されています(Bundle IDは`com.kawauso.LadioCast`で、`C`は大文字です)。Finderでコンテナをゴミ箱に入れるのが、いちばん簡単な方法です。

1. Finderの「移動」メニューから「フォルダへ移動...」(Shift-Command-G)を選び、`~/Library/Containers/`と入力します。
2. フォルダ`com.kawauso.LadioCast`をゴミ箱に入れます。

インストール直後の状態に戻ります。

::: tip
ターミナルからコンテナを削除(`rm`)しようとすると、ターミナルに他のアプリのデータへのアクセスが許可されていない限り、`sudo`を付けても「Operation not permitted」で拒否されることがあります(システム設定、プライバシーとセキュリティ、フルディスクアクセス)。また、サンドボックスのアプリでは、`defaults delete com.kawauso.LadioCast`でも「ドメインが見つからない」と表示されることがあり、削除できません。
:::

## TLS(SSL)で接続できない場合

TLS でサーバーに接続しようとして「接続できませんでした」と表示される場合は、次の点を確認してください。このメッセージは、ほかの接続の失敗と同じ文言のため、原因までは分かりません。

### Icecast ストリーマー

- IP アドレスではなく、ホスト名を入力してください。Ladiocast は、サーバー証明書を、入力した名前に対して検証します。ホスト名に対して発行された証明書は、IP アドレスとは一致しません。
- 入力するホスト名は、証明書に書かれている名前のどれかである必要があります。
- 証明書は、公的に信頼された認証局が発行したものである必要があります。Ladiocast は、macOS のキーチェーンではなく、同梱したルート証明書の一覧(Mozilla のもの)で検証します。自己署名の証明書、プライベートな認証局が発行した証明書(キーチェーンに追加していても同様です)、期限切れの証明書は、拒否されます。
- 平文のポートではなく、サーバーの TLS 用のポートを設定してください。
- Mac の日付と時刻が、正しいことを確認してください。

### RTMP ストリーマー

`rtmps://` の接続は、暗号化されますが、Ladiocast は、サーバー証明書を、まだ検証しません。そのため、証明書の問題では、失敗しません。失敗する場合は、お使いのサービスが指定する URL とポートを確認してください。

## 不具合と思われる動作をレポートしたい場合

コンソール(`/アプリケーション/ユーティリティ/コンソール`)を起動して、当該動作時にコンソールログに何か書かれないか見て下さい。書かれるものがあればそれをブログのコメントやメールに添えてレポートをお願いします。
